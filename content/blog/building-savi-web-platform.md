# Building SAVI

Building a web application is not just a matter of creating pages. The difficult part is connecting the pages into a coherent product: onboarding should lead naturally into the main experience, actions should have clear outcomes, and the interface should remain understandable as more features are added.

For **SAVI**, I approached the product with that system-level mindset.

## Start With the User Journey

Before worrying about visual details, I define the path a user is expected to follow. What is the first useful action? What information is needed? What should happen after a task is completed?

Mapping that flow early helps prevent a common problem in web products: individual screens that look good but do not work together.

## Why Next.js and Firebase

SAVI uses a modern web stack built around **Next.js, React, TypeScript, Tailwind CSS, and Firebase**. This combination gives me a productive environment for building responsive interfaces while connecting authentication and application data to a managed backend.

The important architectural idea is separation of concerns. UI components should present state, while the data layer handles persistence and application rules. That structure makes future changes safer.

## Designing for Responsive Use

A responsive application should not simply shrink on smaller screens. Navigation, spacing, buttons, cards, and information density must all adapt.

On desktop, more information can be visible at once. On mobile, the interface benefits from stronger hierarchy and deliberate stacking. I treat these as different compositions of the same product rather than two completely separate designs.

## What I Learned

SAVI reinforced one of my core development principles: **a successful application is a system of connected decisions**. Product flow, data structure, visual hierarchy, and technical architecture all influence one another.

That is why I prefer building features around real user journeys instead of isolated UI screens.
